# Ad Growth Console

一个静态、无第三方依赖的广告投放流程原型，用于检查 Google Ads、Meta 和 TikTok 的方案准备、人工审核、任务执行及复盘链路。

[English](README.md)

**所有数据和操作均为本地演示。** 原型没有连接真实广告账户、读取人群名单、调用 AI、上传素材、启动广告或获取真实日报。身份切换和任务认领用于演示业务规则，不构成登录认证或权限保护。

## 本地打开

在仓库目录运行：

```sh
python3 -m http.server 8080
```

浏览器打开 [http://localhost:8080](http://localhost:8080)。页面目前以中文为主。

生成后的页面无需安装第三方包。Python 3 用于启动本地服务和构建；Node.js 用于运行流程测试及 npm 命令。无需执行 `npm install`。

## 建议体验顺序

1. 新建投放方案，或选择一个已有示例计划，在其下新增广告组。
2. 选择具体素材版本，按需要加入人群包。
3. 模拟检查当前执行电脑上的素材文件。
4. 核对示例文案、选择落地页，并保存演示追踪链接。
5. 对完整方案版本进行人工审核。
6. 提交、领取搭建任务，分别体验全部完成、部分失败和结果待确认。
7. 分别查看启用和实际投放状态，再模拟日报并建立下一轮测试组。

六个一级页面为工作概览、投放管理、资源库、执行中心、日报复盘、团队设置。资源库包含素材、人群、落地页与追踪记录。

## 可以检查的设计

- 单平台及多平台方案，分别维护账户、计划、广告组和广告编号。
- 人工审核固定版本，关键内容发生变化后重新审核。
- 任务所有权、按电脑区分的素材缓存、失败项重试，以及未知结果的先核实后处理。
- 历史执行记录保留当时选定的素材、人群、页面和追踪链接。
- 可选的付费、使用、活动和自定义人群；文件选择只登记元数据。
- 演示日报将平台归因转化与业务注册、首次订阅分别展示。

名称、编号、页面、指标和执行结果均为示例。`example.com` 链接是占位地址。文案和页面推荐使用固定示例逻辑；素材准备及人群匹配不读取文件内容，也不联系平台。

## 保存范围与未接入能力

状态保存在当前浏览器的 `localStorage`，按访问地址和浏览器配置隔离。不同电脑和浏览器不会共享记录；清除站点数据会清除演示历史。保存失败或容量不足时，页面会明确提示，不把未保存的内容显示为已保存。

真实广告 API、邮件／人群名单、SSO、共享存储、云盘、定时任务以及自动唤起 Codex 均未接入。可以将任务说明交给执行者或 AI；打开网页不会自动启动其他应用。没有 Codex 也可以在普通浏览器中体验。

## 构建与测试

```sh
npm run build
npm test
```

等效命令：

```sh
python3 scripts/build.py
node tests/workflow.test.cjs
node --test tests/storage.test.cjs
```

测试检查本地状态、事件流程和浏览器存储，不证明真实平台已接入、投放有效或具备生产安全能力。修改布局或渲染后，还需要通过浏览器检查页面。`npm run check` 用于检查公开发布文件。
